# 사진 얼굴 블러 파이프라인

노인복지센터 사진 게시판은 어르신 얼굴을 담는다. 이 파이프라인이 조용히 실패하면 개인정보가 그대로 공개된다.

## 불변식

> **파이프라인이 실패했을 때 무블러 이미지가 게시되지 않는다.**

"블러가 적용된다"가 아니다. 적용에 실패했을 때 무엇이 일어나는지가 지켜야 할 지점이다. 실패는 전부 **업로드 거절**로 끝나야 하고, 무블러 이미지로 대체(fallback)해서는 안 된다.

### 이 불변식이 덮지 않는 것

두 가지는 원리상 여기서 막을 수 없다. 사양이 강제하는 척하면 안 되므로 명시한다.

- **감지 실패(false negative).** `tinyFaceDetector`가 옆얼굴·역광·작게 찍힌 얼굴을 놓치면 감지 결과가 정상적으로 "얼굴 0개"다. 파이프라인은 실패하지 않았으므로 `plain` 경로로 무블러 게시된다. 자동 감지가 놓친 얼굴은 관리자가 **수동 보정**(5단계)으로 덮는 수밖에 없다.
- **관리자의 명시적 해제.** `toggleFaceBlur`는 의도된 기능이다 — 동의를 받았거나 얼굴이 없는 사진을 원본으로 보이려는 용도다. 불변식은 사고를 막는 것이고, 관리자의 의식적 결정은 그 대상이 아니다. 아래 "공개 표시 규칙" 참조.

## 단계

1. **감지 — 브라우저** (`app/admin/photos/[id]/upload/PhotoUploader.tsx`)
   `compressImageFile()`로 먼저 축소한 뒤 face-api.js `tinyFaceDetector`로 얼굴 좌표를 뽑는다. 압축을 먼저 하는 이유는 업로드 파일과 좌표의 기준 이미지를 일치시키기 위해서다.
   `detectFaces()`는 `{ ok: true; regions } | { ok: false; reason }`을 반환한다. 모델 로드 실패·이미지 디코딩 실패를 **빈 배열로 뭉개지 않는다** — 뭉개면 서버가 "얼굴 없는 사진"으로 처리해 무블러 원본을 게시한다. 실패한 파일은 업로드에서 제외하고 관리자에게 파일명과 함께 알린다.

2. **좌표 변환** (`lib/blur-regions.ts`)
   원본 기준 좌표를 리사이즈본 기준으로 스케일한다. `sharp.extract`는 영역이 이미지 경계를 1px라도 벗어나면 throw하므로 라운딩 결과를 반드시 안쪽으로 클램프한다. 변환 후 4px 이하이거나 이미지 밖인 영역은 제외한다.

3. **합성 — 서버** (`lib/photo-blur.ts`)
   `composePhotoUpload(buffer, faceRegions)`:
   - `faceRegions`가 비면 → `kind: "plain"`, 압축본 하나만.
   - 남은 영역이 있으면 → `kind: "blurred"`, 블러본과 원본 압축본 둘 다.
   - **얼굴이 감지됐는데 남은 영역이 0이면 → `ok: false`.** 무블러 압축본으로 대체하지 않는다.

   `composite()`를 루프에서 체이닝하면 마지막 것만 적용되므로 배열로 모아 한 번에 넘긴다.

4. **저장**
   블러본은 `<folder>/blurred/`, 원본은 `<folder>/original/`에 올린다. `photos.url`이 블러본, `original_url`이 편집 기준 원본이다.

   `original_url`은 "블러가 걸린 사진"의 표지가 아니다 — 수동 보정도 원본이 없던 사진의 현재 `url`을 `original_url`로 승격시킨다(5단계). 블러 적용 여부를 나타내는 건 `is_face_blurred` 하나뿐이고, 그 값은 업로드 시점 이후 `toggleFaceBlur`로 독립적으로 바뀐다.

5. **수동 보정** (`app/actions/admin/applyManualBlur.ts`)
   관리자가 직접 영역을 지정한다. 여기도 유효 영역이 0이면 에러를 반환한다. 편집 기준은 `original_url ?? url`이고, 결과는 새 `url`이 되며 기준이 됐던 이미지가 `original_url`로 남는다.

## 공개 표시 규칙

공개 페이지가 무엇을 렌더하는지는 `is_face_blurred`가 정한다.

| `is_face_blurred` | 공개 페이지가 내려보내는 것                     | 갤러리가 표시하는 것 |
| ----------------- | ----------------------------------------------- | -------------------- |
| `true`            | `url`만 (`original_url`은 `null`로 지워 보낸다) | `url` (블러본)       |
| `false`           | `url` + `original_url`                          | `original_url`       |

`app/(public)/board/photos/[id]/page.tsx`가 `original_url`을 지우는 것은 **URL 은닉이지 접근 통제가 아니다.** R2는 `pub-*.r2.dev` 공개 도메인으로 서빙되므로 키를 아는 사람은 `original/` 오브젝트를 그대로 읽는다. 원본을 진짜로 막으려면 버킷을 비공개로 돌리고 서명 URL을 써야 한다 — `docs/backlog.md` 참조.

## 진입점

- `app/api/upload-photo/route.ts` — 사진 게시판 업로드. 블러 적용 불가는 **422**로 응답한다.
- `app/actions/admin/uploadPhoto.ts` — 수상 내역·히어로 이미지 업로드. 현재는 얼굴 좌표 없이 호출된다.

둘 다 3단계 합성을 `lib/photo-blur.ts` 한곳에서 가져다 쓴다. 예전에는 각자 복제해서 갖고 있었고, 한쪽에만 있던 무블러 대체 경로가 이 불변식을 깨고 있었다.

## 오브젝트 수명주기

블러본과 원본은 **함께 존재하거나 둘 다 없거나**여야 한다. 짝이 깨진 채 남는 쪽이 원본이면 무블러 얼굴 사진이 공개 버킷에 방치된다.

- **업로드 부분 실패** — `uploadAllToR2`가 한쪽만 성공한 경우 성공분을 지우고 원래 오류를 올린다.
- **DB 저장 실패** — R2에는 올라갔는데 `savePhotoMetadata`가 실패하면 클라이언트가 `discardUploadedPhoto`로 회수한다.
- **삭제 실패** — R2 삭제가 실패하면 **DB 행을 지우지 않는다.** 행을 지우면 키를 잃어 그 오브젝트를 다시 찾지 못한다. 관리자에게 실패를 알리고 재시도하게 한다.
