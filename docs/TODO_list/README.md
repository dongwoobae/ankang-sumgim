# TODO_list — 센터의 답이나 자료가 있어야 풀리는 작업

코드만으로는 끝낼 수 없고 **센터(발주자)가 답하거나 자료를 줘야 착수할 수 있는 것**을
문서당 하나씩 모은다. 개발자가 혼자 착수할 수 있는 기술 부채는
[`docs/backlog.md`](../backlog.md)에 둔다.

## 규칙

1. **문서 하나 = 문제 하나.**
2. **착수 시점을 폴더로 나눈다 — `<상태>/<주제>.md`.**

   | 폴더    | 뜻                                                       |
   | ------- | -------------------------------------------------------- |
   | `now/`  | 지금 착수 가능. 필요한 답·자료가 이미 있다.              |
   | `wait/` | 센터의 답·자료를 기다린다. 오지 않으면 하지 않아도 된다. |

3. **트리거가 충족되면 `git mv wait/x.md now/x.md`로 옮긴다.** 본문의 "막힌 이유"도
   같이 고치고, 링크는 `rg -n TODO_list docs/`로 찾아 함께 갱신한다.
4. **처리하면 파일을 삭제한다.** 언제 무엇이 닫혔는지는
   `git log --diff-filter=D -- docs/TODO_list/`가 답한다.
5. **삭제할 때 결론은 `docs/specs/`로 옮긴다.** 이 폴더는 "아직 안 정한 것",
   specs는 "정한 것"을 담는다.
6. **여기에 목록을 만들지 않는다.** 남은 것은 `ls -R docs/TODO_list`가 답한다.

## 문서 형식

제목 아래 네 가지를 둔다.

- **막힌 이유** — 왜 지금 못 하는지. 추측이 아니라 실측 근거로.
- **트리거** — 무엇이 충족되면 착수 가능한지.
- **착수 시 정할 것** — 선택지와 각각의 함의. 센터에 물을 것은 그대로 읽어 줄 수 있는
  문장으로 적는다.
- **출처** — 날짜.

## 주의

여기 적힌 건 결정이 아니다. 착수할 때 그 시점의 코드와 검색 결과로 전제를 다시 확인한다.
